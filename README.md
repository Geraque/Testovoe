# Тестовое задание: разработчик интеграций

Решения двух задач: распределение накладных по заявкам ГУ-12 и сверка складского журнала с документами 1С. Исходное условие сохранено в `Тестовое_задание.docx`, входные файлы в `data/` не изменены.

## Как запустить

Нужен Python 3.10 или новее. Используется только стандартная библиотека, установка пакетов не требуется. Из каталога с этим README:

```bash
python main.py
python -m unittest discover -s tests -v
```

На Windows вместо `python` можно использовать `py -3`. Результаты прогона уже приложены: [result_z1.json](result_z1.json) и [result_z2.json](result_z2.json). Повторный запуск перезаписывает их.

Другие каталоги можно передать явно:

```bash
python main.py --data-dir data --output-dir output
```

По умолчанию пути считаются от расположения `main.py`, поэтому запуск по абсолютному пути работает из любого каталога. Явно переданные относительные пути считаются от текущего рабочего каталога. Ошибка чтения или обработки данных завершает программу с кодом 1 и сообщением в stderr. Обе задачи рассчитываются до начала записи результатов.

## Какие решения принял и почему

### Общие решения

- Алгоритмы отделены от файлового ввода-вывода: их можно проверить на небольших примерах без создания файлов. Входные словари не изменяются.
- Все вычисления количества и массы выполняются через `Decimal`. Запятая в числе заменяется точкой. Дробные JSON-числа читаются сразу как `Decimal`, без промежуточного `float`.
- В результате числа преобразуются в `float`, чтобы сохранить требуемый JSON-формат с числами, а не строками. После преобразования арифметика не выполняется. Остатки не округляются до десятых: например, `11.41` сохраняется.
- Повторяющиеся номера заявок/накладных и ID записей/документов считаются ошибкой, чтобы не потерять данные при формировании словарей. Проверяются конечность чисел, допустимость количества вагонов, положительность строк движений и корректность периода заявки.
- Коды номенклатуры, клиенты, МОЛ и ID контрагентов сравниваются точно. Справочники номенклатуры и контрагентов использованы для анализа данных; для расчёта достаточно кодов и ID из движений. По имени или ИНН записи не объединяются.

### Задача 1

- Начало и конец периода включаются целиком как календарные дни. Время учитывается при сортировке отправок и поступлений заявок.
- Заявки с префиксом `Отозвана` полностью исключаются. Остальные присутствуют в результате, даже если у них нет накладных.
- При полном совпадении начала периода и времени поступления сохраняется порядок входного файла. То же правило действует при одинаковом времени отправки накладных. Номер заявки не используется для сортировки.
- Просроченная незаполненная заявка принимает вагоны до исчерпания вместимости. Будущая заявка не принимает даже при отсутствии других свободных мест.
- `sverh_zayavki` — число вагонов сверх заявки, не логический флаг. Обычная часть и превышение записываются отдельными строками, даже если относятся к одной заявке; у обычной части значение 0.
- Масса распределяется методом наибольших остатков в единицах 0,1 т: целые доли вниз, оставшиеся десятые — частям с наибольшими дробными остатками. При равенстве приоритет у более ранней части. Это сохраняет общую массу и не создаёт отрицательных частей. Если входная масса точнее 0,1 т, сначала округляется общий итог по `ROUND_HALF_UP`.
- Отсутствующий, пустой или `null` клиент накладной означает `bez_klienta`. Группы `bez_zayavki` создаются только при наличии таких остатков.

### Задача 2

- Повторные строки одного кода суммируются перед сравнением. Одна позиция `2 + 3` равна позиции `5`: это один материал в одном количестве, независимо от разбиения на строки.
- Окно даты включительно: от даты записи минус 2 календарных дня до плюс 14. Месяцы и годы обрабатываются календарной арифметикой.
- Конкуренция нескольких записей за документ разрешается последовательной обработкой: дата записи, затем числовой ID. Кандидаты ищутся среди ещё не использованных документов. Первой связывается более ранняя запись; следующая при отсутствии свободных кандидатов попадает в `ne_najdeno`. Это выбранная трактовка не заданного в условии порядка.
- При нескольких кандидатах связь не создаётся, документы не резервируются. Запись остаётся неоднозначной; последующая обработка не запускает повторное связывание. Список кандидатов отражает состояние на момент обработки записи. Глобальное восстановление соответствий не выполняется.
- Только статус `vydano` участвует и в связывании, и в корректировке остатков. Отменённые и черновые записи не являются фактическими движениями.
- Для `vozvrat` не задан соответствующий вид документа 1С. Поэтому активный возврат остаётся несвязанным, входит в `ne_najdeno` и корректирует остатки. Непустой `kontragent_id` означает возврат от подрядчика, иначе — от своих. `iskhodnaya_id` не является связью с 1С и не отменяет движение возврата.
- Связанные выдачи не корректируют остатки повторно. Все несвязанные, включая неоднозначные, корректируют остатки по формуле задания; возможное повторное отражение факта требует ручной сверки.
- Счёт ровно `10.07` относится к подрядчикам, остальные — к МОЛ. Повторяющиеся строки остатков суммируются. Отсутствующая пара МОЛ/код или контрагент/код начинает с нуля. Отрицательные остатки сохраняются как признак расхождения; нулевые исключаются только у подрядчиков.
- Расчёт выполняется по всему переданному снимку: дата отсечения в задании не указана. Неизвестный тип активного движения журнала — ошибка, неподдерживаемый вид документа 1С не является кандидатом.

## Проверки

Тесты написаны на стандартном `unittest`. Проверены на Python 3.13.5; отдельный запуск под 3.10 не выполнялся, код использует синтаксис и API, доступные в 3.10.

| Правило задачи 1 | Тесты в `tests/test_task1.py` |
| --- | --- |
| 1. Отозванные исключаются | `test_rule1_withdrawn_applications_are_excluded` |
| 2. Клиенты разделены | `test_rule2_clients_do_not_share_capacity_or_overflow` |
| 3. Очередь по началу и поступлению | `test_rule3_start_date_has_priority_over_received_date`, `test_rule3_received_date_breaks_tie_not_number` |
| 4. Порядок отправки | `test_rule4_invoices_sorted_by_timestamp` |
| 5. Начало периода и добор просроченной заявки | `test_rule5_future_application_cannot_accept`, `test_rule5_expired_application_filled_before_current` |
| 6. Разделение и округление массы | `test_rule6_invoice_split_and_mass_preserved`, `test_mass_rounding_uses_largest_remainders_and_stable_ties` |
| 7. Превышение в последнюю подходящую заявку | Три теста с префиксом `test_rule7_` |
| 8. Без заявки и без клиента | Два теста с префиксом `test_rule8_` |

Для задачи 2 проверены виды документов, МОЛ, карточки контрагентов, состав позиций, границы дат, статусы, неоднозначность, однократное использование документа, возвраты, знаки корректировок, точная десятичная арифметика и нулевые/отрицательные остатки. Интеграционные тесты сравнивают оба полных JSON с вручную рассчитанными ожиданиями, проверяют повторный запуск и ошибки входных файлов.

## Результат на выданных данных

- Заявка `0000700188` получает 30 вагонов, `0000700120` — 40, `0000700310` — 7; A1005 делится на 7 и 7 вагонов по 413 т.
- Заявка `0000700050` получает 20 обычных вагонов и 2 сверх заявки; `0000700333` — 9, `0000700400` — 5. G3001 остаётся без заявки, X9001 — без клиента.
- Связи: `1 → d-101`, `3 → d-103`, `6 → d-105`. Не найдены: `2, 5, 8`. Неоднозначность: `4 → [d-106, d-107]`.
- Остаток Н-003 у Кузнецова: `27.31 − 15.9 = 11.41`; Н-002 у Петрова: `12 − 4 + 1 = 9`; Н-002 у k-3: `8 + 4 − 1 = 11`.

## Что насторожило и что сказать кладовщице или бухгалтерии

1. Карточки k-1 и k-2 имеют одинаковые имя и ИНН: проверьте дубликат справочника; автоматически их не объединяю.
2. Для записи 2 документ d-102 датирован на 20 дней позже: сверьте даты и задержку проведения; окно +14 дней не расширяю.
3. Для записи 4 подходят d-106 и d-107: проверьте, не задвоена ли передача, и укажите правильный документ.
4. Возврат 5 связан с выдачей 4 только через iskhodnaya_id: нужен отдельный вид и идентификатор документа возврата 1С.
5. Запись 8 от 31.03.2026 значительно старше остальных: проверьте дату, незакрытую выдачу и полноту выгрузки документов.
6. У несвязанных выдач могут уже быть движения в остатках 1С: расчёт по заданной формуле требует ручной сверки записей 2 и 4.
7. Дата снимка остатков не указана: согласуйте её с датой отсечения журнала и выгрузки документов.
8. X9001 без клиента, а G3001 отправлена до начала заявки: заполните клиента и проверьте основание ранней отправки.
